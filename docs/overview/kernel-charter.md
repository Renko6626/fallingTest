# 落沙法术对战（暂名）· 内核顶层设计总纲

版本 v0.1 · 2026-08-15 · 状态：草案
适用范围：游戏内核（模拟、联机、物理、确定性纪律）。不含玩法数值、美术、音频、发行。

---

## 0. 文档定位

本文是内核的宪法：规定**什么必须永远成立**、**什么明确不做**，不规定代码怎么写。

- 实现与本文冲突时，以本文为准；要突破，先改文档并在 §11 决策日志留痕。
- 已决事项不在代码评审中反复重开；待决事项一律附判定条件与判定时点。

## 1. 产品需求与硬约束

产品一句话：东方 Project 主题（构想中的定位，非内核约束）的 1v1 法术对轰游戏，运行在 Noita 式落沙世界里——**材料反应与环境连锁（点燃油、毒液泄漏、连环爆炸）是玩法核心，不是表现层装饰**。

硬约束：

- 联机对战，1v1 为主（协议不排除更多人，产品不承诺）。
- 法术为**赛前构筑 loadout**，对局内无合成、无拾取。
- 地图小-中、固定、全图常模拟。模拟基准 640×360、上限 1280×720，1 cell = 1 显示像素，整数倍放大。
- 平台 Windows↔Windows，**同版本二进制互联**，不承诺跨平台。
- 模拟锁 60Hz 固定 tick。
- 功能面：落沙 CA、数据驱动材料反应、材料破坏、像素刚体、大于 1 格/tick 的高速流体与弹体。

## 2. 第一性原则（全项目最高约束）

- **P1 确定性 by construction**：世界演化是（初始状态，输入序列）的纯函数。任何未同步量——本地时钟、本地相机、本地帧率、OS 随机——不得影响逻辑状态。确定性只能从第一天构造出来，不能事后补（Noita 的反面教训）。
- **P2 逻辑/表现硬隔离**：核心 sealed，边界只有三条通道——InputFrame 进、Channel A 状态快照出、Channel B cosmetic 事件出。表现层永不回写核心。
- **P3 状态可快照、可哈希、可回放**：这是 SyncTest、desync 诊断、竞技回放与未来 rollback 的共同地基。
- **P4 并行必须可证明**：只允许"读写集不相交"可证明的并行方案，以及可交换可结合的合并操作（如脏矩形的 min/max）。不能给出论证的并行不许进核心。
- **P5 数据即确定性输入**：材料表、反应表、法术表、地图与代码同级，全部纳入版本指纹。两端数据表不一致视同版本不一致。

## 3. 联机模型

- 拓扑：1v1 对等 P2P，只交换输入。开发期用房间码 + 直连或自建 VPS relay；发行期若上 Steam 则切 GNS + SDR。NAT 穿透方案不构成内核约束。
- 同步方式：**延迟制 lockstep**，输入延迟 3–4 帧（50–67ms）。双端对称等待，天然无主机优势——这正是对战公平性的来源。带宽预算 ≤ 2 KB/s。
- 体感策略：表现层做零延迟预反馈（瞄准线、施法音效、起手动画本地立刻播），弹体在确认帧生成。
- 升级路径：核心接口按 rollback 设计（纯函数 step、可快照、可哈希），是否启用 rollback 是 M6 的决策门，不影响之前的任何工作。
- 对局握手：构建指纹 + 数据表指纹 + 地图/种子 + 双方 loadout，共同构成对局初始状态。loadout 在握手期交换确认，之后进入纯输入同步。
- desync 处置（对战版）：全局哈希定期比对 + chunk 级增量哈希定位分叉；发现即终止对局、双端落盘 replay 供修复。**v1 不做运行时状态修复**（那是大世界备胎，见 §9）。
- 回放是一等公民：lockstep 下录输入流零成本，同一份 replay 既是竞技回放也是 bug 复现载体。

## 4. CA 内核：三层模型

**Layer G — 网格层（push，四相棋盘）**

- 64×64 chunk + 每块脏矩形；按 (chunk_x & 1, chunk_y & 1) 分四相位。
- 确定性论证：同相位内任意两块至少隔一整块，单次 cell 更新的影响半径有硬上限 **r ≤ 16**（格内移速 ≤ 4 + 液体色散 ≤ 8 + 余量），故同相位各块读写集必然不相交——任意线程调度得到同一结果；相位间加屏障、按固定顺序执行。这是并行与确定性兼容的完整论证，属于 P4 的示范实现。
- 块内自下而上定序扫描，水平方向按 (y + tick) 奇偶交替消除方向偏置；per-cell tick 奇偶位防止同 tick 跨相位二次移动；相位顺序按 tick % 4 轮换，摊平边界各向异性。
- 逻辑 cell ≤ 4 字节（material / flags / aux）。颜色抖动等表现字段不入状态，由坐标 hash 现场派生。

**Layer P — 稀疏粒子层（高速弹道）**

- 速度超过格内上限即脱格为粒子（定点坐标），并行做纯函数积分与 DDA 路径碰撞查询，**串行按粒子 id 提交落格**，同格冲突 id 小者胜，输家按定序邻格（上、左、右、左上、右上）搜索空位；五邻格全占则沿候选格正上方继续向上搜索最近空格，搜到世界顶仍无空位则确定性出界销毁——**不存在"继续飞行/悬浮"分支**（原文措辞已按 M1 实现修正，见 §11 决策日志 2026-08-30）。
- 粒子 id 按创建顺序分配（创建发生在确定性的网格 pass 内，故 id 序本身确定）。
- 容量硬上限（初值 64k），满则确定性拒绝生成——一切限流规则必须两端一致。
- 法术弹体复用同一套弹道基建（挂 payload 的粒子）。

**Layer F — 场层（扩散量）**

- 气体、温度等扩散型的"场"走全图 pull 双缓冲 pass，天然并行、天然确定，与 G/P 层分工明确。

**反应系统与随机性法典**

- 材料反应 = (matA, matB) → {概率, 产物} 的数据表；约定发起方（如 material id 较小方）防止对称反应双结算。材质数量增长只让表变大，不让规则组合爆炸。
- 一切逻辑随机 = hash(tick, x, y, salt/stream)，与执行顺序彻底解耦。**禁止任何全局顺序消费的 RNG 流**。

## 5. 刚体子系统

- 归属：刚体是同步态的一部分，且与 CA 每 tick 双向耦合，**必须住在核心内**。
- Godot 内建物理**禁止参与逻辑**（不承诺确定性、不可快照、不可手动步进）；纯表现层的碎屑、尸块可用 Godot RigidBody2D，由 Channel B 事件驱动，两端各玩各的。
- 管线：像素体 → marching squares 提轮廓 → 折线简化 → 三角化 → 物理 body；每 tick 按 body id 序把像素**盖章回网格**，CA 对其一视同仁（液体绕流、浮力 = 淹没像素计数、爆炸直接删像素）；位图变化经滞回后重提取 collider，不逐帧重建。
- 引擎选型为待决项（判据见 §11）：lockstep 阶段 Box2D v3 与 Rapier（enhanced-determinism）皆可；进 rollback 前以"快照-恢复-重模拟逐 bit 一致"的 SyncTest 判生死——回滚要求恢复后重算与对端直跑收敛到同一状态，因此快照必须覆盖求解器内部缓存。判负则切 Rapier 的 serde 全状态快照，或自研迷你定点求解器（场景 body 为数十量级，自研可行）。

## 6. 确定性纪律法典（全项目禁令）

- 数值：网格逻辑纯整数；粒子与一切自研运动学用定点（复用 STG 引擎的定点 + BAM 资产）；受控浮点仅允许出现在物理引擎内部与表现层。核心禁用系统数学库超越函数（按 CPU 分派实现是同二进制下唯一的浮点雷区），用 libm crate 或查表替代。
- 容器：禁 std HashMap/HashSet 默认随机 hasher，clippy disallowed_types 强制执法；一切影响状态的遍历必须定序。
- 时序：固定 timestep、固定迭代次数；实体 id 按创建定序分配、按 id 序更新；墙钟与帧率不得进入逻辑。
- 执法机制：SyncTest 双实例逐帧哈希比对为**常驻测试**，从 M0 起 CI 挂 golden replay 回归（录制输入流、断言终态哈希）；台式机 × 笔记本双机哈希流是每个里程碑的必过项。

## 7. 性能预算（按 1280×720 上限配置）

- 网格全图最坏（全屏皆动）：约 7ms 单线程 → 四相并行后约 2ms；日常（脏矩形收敛）< 1ms。
- 粒子 2 万量级：约 0.8ms。物理数十 body：< 0.2ms。
- tick 总预算 ≤ 4ms（最坏情况），对 16.6ms 帧预算留出未来 rollback 重模拟的尖峰余量。
- 渲染：脏块纹理上传 + 调色板 shader，目标硬件 GTX 1050Ti 级。
- 以上为设计估算，M0 落地后以实测校准本节数字。

## 8. 技术栈清单（每项一句理由）

- **Rust**：AOT 同二进制消除 JIT 按 CPU 生成不同机器码的分歧源；借用检查把"相内读写集不相交"编码进类型系统；确定性生态齐全。
- **Godot 4 + gdext**：表现层宿主，复用 STG 引擎已验证的桥模式与三通道边界。
- **GGRS**：lockstep/rollback 会话管理，SyncTestSession 是确定性执法的核心工具。
- **Box2D v3 / Rapier**：二选一，判据见 §5、§11。
- **fixed / libm / FxHash / rayon（有界并行）/ xxHash**：数值、哈希与并行基建。
- **matchbox 或自建 VPS relay**：开发期联机；Steam GNS + SDR 为发行期期权。

## 9. 大世界期权（现在不做，但留缝）

原理已论证可行（Factorio 型：确定性 lockstep + 巨型持久世界 + 区块化），代价是纪律面积与 desync 痛感随会话增长，不是可行性。现在执行三条缝，让大世界从架构分叉降级为功能扩展：

1. 存储 API 从第一天按 chunk 寻址——小图构建下后端就是一整块 flat allocation + 静态页表，近乎零成本。
2. 序列化与哈希天生 per-chunk——SyncTest 与 rollback 本来就需要，等于免费。
3. worldgen 走 seed → chunk 纯函数接口——手工关卡即常函数。

明确**不实现**（只记录设计方向）：与本地相机无关的确定性激活谓词与冻结语义、流式驻留与预取、chunk 级 desync 修复、中途加入的全量状态传输。

## 10. 明确不做（Non-goals）

跨平台联机；场内法杖合成与法术拾取；多于 2 人的对战承诺；MMO / 服务器权威架构；v1 的运行时 desync 修复；Godot 内建物理参与逻辑；为表现效果破坏 P1–P5 的任何"临时方案"。

## 11. 里程碑与决策日志

**里程碑（每项含验收标准）**

- **M0 骨架与执法**：chunk 寻址存储 + 四相调度器 + 沙、水两种材质 + SyncTest 双实例框架。验收：双机 2 万 tick 密集场景零分叉（10 万 tick soak 降级为 M5/M6 发布门，见翻案记录第 5 条）。
- **M1 粒子层**：脱格/落格闭环、DDA 碰撞、容量限流。验收：瀑布与爆炸溅射场景 SyncTest 绿。
- **M2 场层与反应表**：气体/温度 pass + 数据驱动反应。验收：火油连锁 demo 的 replay 终态哈希一致。
- **M3 刚体**：管线全链路 + 盖章耦合 + 破坏重提取。验收：爆炸切割木箱、落水浮沉，SyncTest 绿。
- **M4 玩家与法术**：玩家实体、loadout 数据模型、法术执行原语（弹体/喷射/爆炸/状态效果）。验收：单机镜像自对局可玩。
- **M5 联机对局**：GGRS lockstep + 房间码直连 + 握手指纹校验 + replay 落盘。验收：双机真人对局 30 分钟零 desync。
- **M6 rollback 决策门**：物理快照 SyncTest 判定 → 启用 rollback 或维持延迟制并复评。

**已决（本文即记录）**：确定性 lockstep 路线；三层内核（四相 push + 稀疏粒子 + pull 场）；hash 派生随机；Rust 核心 + Godot 表现层；1v1；赛前 loadout；混合数值制；60Hz；小图全模拟；大世界三条缝。

**翻案记录（2026-08-29 落档，显式推翻 Python 原型时代裁决）**——本文与旧文档冲突时以本文为准，旧文档已加 superseded 标注：

1. **刚体同步路线**：推翻 R3-A"刚体走状态同步 + 客户端预测"（`docs/proposals/2026-06-14-determinism-hardening-r1-r3.md`）→ 刚体属同步态、住核心内、全 lockstep（本文 §5）。翻案依据：平台约束收紧为 Windows 同版本二进制互联（§1），2026-06-14 调研已确认 Box2D 3.1 级别引擎在同二进制下确定性可行，无需再为跨平台妥协；最终判定仍留 M6 SyncTest 决策门。
2. **温度场**：推翻 2026-06-06"fire 走 Noita 式、温度场降级实验分支"裁决（fire spec v2）→ 温度作为 Layer F pull 双缓冲扩散场回归主线（本文 §4）。fire spec v2 的 burn pass / 反应表分工在 M2 实施前按本文重审。
3. **并行语义**：M0.5 的正方形写域 `[chunk−32, chunk+96)²` 4-pass 所有权制 → 四相棋盘 + 影响半径 r ≤ 16 论证（本文 §4 Layer G）。证明结构不同（写域密铺互斥 → 相内间隔一整块 + 影响半径上界），Python 实现不迁移。
4. **RNG key 维度**：7 元组 `(seed, tick, pass_id, x, y, salt, attempt)` → `hash(tick, x, y, salt/stream)`（本文 §4）。pass_id 与 attempt 两维并入 salt/stream 语义，**实现时必须显式保留**——同帧同格多次掷骰返回同值的偏置隐患是 2026-06-06 外部评审确认过的真问题，不得因 key 收敛而丢失。
5. **里程碑验收时长**（2026-08-30）：10 万 tick → **2 万 tick 密集场景**（浇注→沉降入睡→两波长睡唤醒）。依据：本架构无 10 万 tick 独有效应——RNG 无状态纯函数、睡眠是无状态等待（睡 100 与睡 3 万 tick 的 chunk 逐位相同）、世代戳绕回 6 千 tick 已覆盖 23 圈、结构性分叉在触发配置出现后数百 tick 内暴露（M0 实证：tick 583）；时长的边际价值仅为 unknown-unknowns 保险。**10 万 tick soak 保留**，降级为 M5（真人对局前）与 M6 门口各一次的发布级过夜测试。M0 本身已按原标准 10 万 tick 过关（2026-08-30，四配置零分叉）。
6. **M1 粒子相插入 tick 管线第 5 步**（2026-08-30，`docs/superpowers/specs/2026-08-30-m1-particle-layer-design.md` §4）：既有阶段顺序不动，新增阶段——`program-architecture.md` §4 从立宪起就已把粒子层排在第 5 步（`program-architecture.md:125`），M1 实施是把这个占位步骤从空转变为真实生效，仍属协议版本变更，随本条落档。同条一并记录 Layer P 落格语义修正：本文 §4 原文"输家按定序邻格搜索或继续飞行"中的"继续飞行"（悬浮）分支**废除**，改为五邻格全占后沿候选格正上方兜底向上搜索、搜到世界顶仍无空位则确定性出界销毁；§4 原文已同步改写。依据：Task 4 评审（修复轮 1，C1）用 40 颗同位同速沙粒实证——悬浮分支使输家粒子被重置到候选格中心、下一 tick 从该非 air 起点重新判定，若局部仍是同一批全占格局，两 tick 一循环永久活锁（32/40 颗卡死，粒子池不排空）；"或继续飞行"在原文里读作可选分支，实为设计缺陷而非有效选项。判据与详细复现记录见 spec §5 决策记录第 6 条。
