# M0 Rust 内核非正式性能测量

> 文档路径：`docs/perf/2026-08-30-m0-rust-informal.md`
> 运行时版本：Rust（sand-core M0，commit `44a70cb`+）
> 最近更新：2026-08-30 (UTC+8)
> **Status**: Trial（非正式：临时场景、服务器 CPU、后台另有 SyncTest 在跑——112 核余量下干扰可忽略但未隔离。正式基线待 M1 后按 harness-bench 建）

## 环境

Intel Xeon Gold 6330 @ 2.0GHz（112 逻辑核，**单核明显弱于目标桌面 CPU**，估计打 5–7 折）；
release 构建；`replay` 路径（sleep_skip=on，每 256 tick 哈希一次）。

## 场景口径

"worst" = 世界 30–45% 填满水后整体崩塌——**全图同时活跃**的病态上限，
真实对局的活跃占比远低于此。前 300 tick 均值 ≈ 持续最坏；1200 tick 均值含沉降尾巴。

## 对总纲 §7 预算的校准

- **640×360 基准图**：全活跃最坏 ~3ms（8T）——预算内富余，桌面 CPU 上估 ≤2ms。✅
- **1280×720 上限图**：全活跃最坏 ~8ms（8T）> 总纲 4ms 目标，但 (a) 全活跃是病态口径；
  (b) 桌面单核快 1.5–2×，估 4–5ms；(c) 16.6ms 帧预算内无压力——挤占的是 rollback 重模拟余量。
  §7 的"全图最坏 7ms 单线程"估算实测为 23ms（本机）——**单线程估计偏乐观 3×，
  并行后落回预算附近**。M1 后用正式 bench 复校 §7 数字。
- **睡眠常态 < 0.1ms**：chunk 级休眠工作正常，静止世界近零成本。

## "地图能做多大"

- **内存不是限制**：4 B/cell → 720p 全图 3.7MB，4096×2048 也才 33MB。
- **真实限制 = 同时活跃面积**：本机 ~100 万活跃 cell ≈ 8–10ms（8–16T）。
  睡眠生效时地图尺寸几乎免费，1080p 全图崩塌都能 60Hz。总纲"小-中图全模拟"是保守的。
- **前视 caveat**：M1 velocity/粒子、M2 反应表会抬高每 cell 成本；**Layer F pull 场是
  每 tick O(全图) 的**——场层落地后"睡眠让大图免费"不再成立，届时大图成本下限 =
  场层全图 pass，需要实测后重估本节结论。

## O1 活矩形前后对照（2026-08-30 当日实施，spec `2026-08-30-o1-live-rect-design.md`）

同机同口径，8 线程，ChunkSleep（M0 语义）vs LiveRect：

| 场景 | ChunkSleep | LiveRect | 倍率 |
|---|---|---|---|
| sparse（640×384 三股细流，`data/scenarios/sparse.ron`） | 0.372 ms | **0.136 ms** | **2.7×** |
| worst_720p 前 300t 全活跃 | 9.5 ms | 7.8 ms | 1.2×（崩塌期矩形仍 < FULL） |
| sleep_720p 全静止（3 次重跑区间） | 0.05–0.10 ms | 0.05–0.06 ms | 持平（追踪开销不可见） |

等价性证据：既有 golden 用 LiveRect 重放哈希一字不变；六配置 SyncTest
（{1,N 线程} × {Full, ChunkSleep, LiveRect}）CI 绿。720p 全活跃最坏从 ~8ms
改善到 ~7.8ms，稀疏（最常见玩法区间）收益 2.7×——"与 Noita 的最大单项差距"已回收。

## 与 Noita 对照（参数出处：`docs/reference/noita-deep-dive.md`）

| | Noita | 我们（M0） |
|---|---|---|
| 世界形态 | 无限流式，驻留 bubble ≈ 12×512² ≈ 314 万 px [社区] | 固定小-中图全模拟（720p 上限 92 万 cell） |
| 模拟调度 | 64×64 chunk + dirty rect + 4-pass 棋盘 [官方] | 同构（64×64 + chunk 休眠 + 四相），另加确定性契约 |
| 活跃集 | dirty 驱动，典型远小于驻留集 | 同；全活跃病态口径下 720p ~8ms（本机 8T） |
| 每 cell 成本 | 材质 400+、velocity、反应、粒子——刻意低分辨率换 CPU 预算 [官方] | 目前仅 2 动态材质 + 单格移动，成本会随 M1–M3 上涨 |
| 确定性/联机税 | 无（单机，非确定） | 哈希树 + SyncTest + lockstep 语义约束 |

结论：调度架构与 Noita 同构，M0 规则复杂度远低于它，故同活跃面积下我们目前更快
是预期内的、**不可外推**；等 M1（velocity/粒子）与 M2（反应+场）落地后每 cell 成本
才可与之对齐比较。驻留规模上 Noita 的 bubble（314 万 px）≈ 我们上限图的 3.4 倍，
但其中活跃模拟同样是 dirty 驱动的小子集——两边的"能跑多大"都由活跃面积而非驻留面积决定。
