# 提案：切换到 Noita 式逐像素反作用浮力

## 0. 一句话

把 §5 的"采样水面线 → 阿基米德公式"换成 Noita 式"刚体像素碰到液体就弹粒子 + 在该点施反作用力"，
**同时放弃浮体睡眠**（施力 `wake_up = true`）。触发条件见 §5；在此之前维持现状。

## 1. 现状（2026-09-03 收口）

- 浮力 = 接触门控水面线 `h`（`crates/sand-core/src/body.rs` `surface_line`）+ 像素连续中心分数计权
  `n_sub = Σw` + `F = n_sub·ρ_liq·g` 施于加权质心 + 线/角阻力（`K_DRAG`）。
- 浮体**能入睡**（施力不唤醒，spec 决策记录第 11 条）；睡眠浮体在周围 chunk 有写入时重采 `h`，
  与入睡时相差 ≥ `WAKE_H_ROWS = 2` 行即唤醒（第 15 条，`Body::last_h` 入哈希）。
- 三天里这条路线修过的坑：远场采样穿墙（隔壁水槽让地上箱子悬浮）、水丘骗采样让木条自旋到
  22 rad/s、整行台阶睡不着、向上扫连续液体塌到气泡、斜面邻格被本体挡住、唤醒门槛按体积比例
  设导致睡了又醒 11 次、水退后睡眠浮体挂在半空。**每一条都是"力的大小来自对环境的采样"这一
  结构带来的**，Noita 式没有这一层。

## 2. Noita 方案（社区复原，未确证——`docs/reference/noita-deep-dive.md:300`、`:429`）

tick 末遍历刚体像素的世界坐标：碰到液体/沙的像素 → 该格弹入粒子系统（飞溅）+ 在该点按
`velocity_at_point` 施反向力与阻尼。没有公式、没有水面线、没有淹没体积。

> **2026-09-03 更正**：wiki 官方组件文档显示 `PhysicsBodyComponent` / `PhysicsBody2Component` 带
> **`buoyancy: float = 0.7`**，外加 `linear_damping` / `angular_damping` / `allow_sleep`。一个每 body 的标量
> 浮力系数只能配"算出淹没量 × 系数"的公式浮力（Box2D `b2BuoyancyController` 形态），所以 Noita 的浮力
> **不是**纯逐像素涌现，本节描述的只是排开/飞溅那一半。这削弱了本提案的前提：Noita 走的其实是与我们
> 同源的"公式 + 阻尼 + 可睡"路线，差别只剩水面线怎么取（未知）与是否在水里睡。§3–§5 的得失对照仍成立，
> 但"切到 Noita 式"应改读为"切到无水面线的逐像素反作用式"，那是我们自己的方案，不是 Noita 的。

从 Box2D 语义推出的两个性质（与 Noita 可见行为吻合，非一手资料）：
- 力经 `ApplyForce(wake=true)` 施加 ⇒ **液体里的刚体永远醒着**，Noita 的木桶在水里始终轻晃。
- 平衡是**动态的**：下沉 → 底边撞进新水格 → 被顶回 → 留下空腔 → 再沉。力正比于每 tick 新接触
  的像素数 ≈ 周长 × 相对速度，**不正比于体积**。

## 3. 切换后得到什么

| 项 | 现状 | Noita 式 |
|---|---|---|
| 隔墙水槽 / 架高水槽 / 木条架在浮箱上 | 靠接触门控挡住 | 天然免疫（力只在像素重合处产生） |
| 水丘、水帘流过顶面侧面 | 靠"取最低"兜底 | 天然免疫（静止刚体的格不会被液体进入） |
| 水退了浮体跟着落 | 需要唤醒规则（第 15 条） | 天然成立（刚体本来醒着，接触没了重力接管） |
| 新增状态 | `last_h` 入哈希 | 无 |
| 采样/特判代码 | `surface_line` 约 100 行 + 唤醒逻辑 | 盖章循环里加一个分支 |

## 4. 切换后失去什么

1. **阿基米德与 `density` 的数据语义**。木头 12/水 16 ⇒ 75% 吃水、石头 40 ⇒ 沉，现在是从数据表推出
   来的、与尺寸无关。Noita 式的力 ∝ 周长，大小箱子吃水不同，浮沉阈值变成一个要调的常数；要保住
   "density 决定浮沉"，得在逐像素力里显式乘 `(ρ_liq − ρ_body)` 并按面积归一，那已是第三套方案。
2. **静态入睡**。浮体永远醒 ⇒ 每 tick 反盖章/盖章、弹水、周围 chunk 永远脏。**实测**（2026-09-03，
   §6 第 1 步的安全出口：三处施力改 `wake_up = true`，crate_yard 旧场景 5000 tick 1T）：0.78 →
   **1.70 ms/tick**，三个浮体全程醒着 ⇒ **≈ 0.3 ms/浮体/tick**，几乎全是 CA 被拖着不睡的钱，不是
   引擎的钱。spec §3"静止世界零写入"对浮体失效。
3. **Noita 的分母我们没有**：Noita 只模拟玩家周围几屏，区域外刚体冻结，同屏浮体就几个；我们是
   1v1 lockstep 全场模拟，没有"远处"可卸载（按谁的距离裁都会分叉）。场地小、浮体是法术召出的
   箱子与碎片，量级十几个 ⇒ 1–2 ms/tick，吃预算但不致命。
4. **视觉**：物件在水里永远轻晃（Noita 接受了这一点）。

## 5. 何时切（触发条件，满足任一即重开本提案）

- 唤醒规则（第 15 条）再出一次需要新特判才能修的边角。
- 浮体数量级明确 < 10 且目检嫌"睡着的箱子太死"。
- M4 法术需要"液体推动物件"的强互动（水柱冲箱子、油面推桶）——逐像素反作用天然给横向推力，
  采样式给不了。

## 6. 怎么切（最小步）

1. 安全出口（一行）：`physics.rs` `apply_force_at` / `apply_drag` / `apply_angular_drag` 改
   `wake_up = true`；`apply_buoyancy` 删睡眠分支与 `last_h`。这一步不换公式，只换"水里不睡"，
   用来先量代价。
2. 换公式：在 `stamp_body` 的排开分支（`Category::Liquid | Powder` ⇒ 弹粒子）同点施
   `−k·(v + ω×r)` 的反作用与一个向上分量；`surface_line` 整段删除。是否保留 `(ρ_liq − ρ_body)`
   因子按 §4 第 1 条决定。
3. 行为测试要改的：`wood_crate_floats_stone_crate_sinks`（吃水深度不再是 75%）、
   `floating_crate_settles_and_stops_ejecting_water`（永远轻晃，改为"振幅有界"）、
   `plank_in_deep_pool_does_not_spin_up`（入睡断言删）；保留的：隔墙水槽两条、水退跟落。
4. golden 重录、六配置 SyncTest、bench 对照 `docs/perf/`。

## 7. 不切也该做的（2026-09-03 已处理）

- 顶面载荷项（"5-lite"）：**已落地**（决策记录第 16 条），判据是"高于周围自由面"而非 `y < h`。
- 排开粒子带 `ω×r` 切向速度：**试过、撤回**——横摇中的木条把水甩得不对称，接触列 `h` 跟着抖、
  维持横摇，3000 tick 睡不着。若日后切到本提案的逐像素反作用，这一项会自然回来（力与出射都在
  接触点算），到时要连带解决横摇自激。
