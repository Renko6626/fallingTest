# 粉末堆积的系统性方向偏置：行扫描定向改哈希相位

> 文档路径：`docs/proposals/2026-08-31-powder-scan-direction-bias.md`
> 运行时版本：Rust（内核）+ Godot 4 + gdext（表现层）
> 最近更新：2026-08-31 (UTC+8)
> **Status**: Implemented

**订正总纲正文**：本提案修改 `docs/overview/kernel-charter.md:58` 的"水平方向按 (y + tick) 奇偶交替消除方向偏置"。不属翻案（未推翻任何编号裁决），归入 §11 **实施期决策第 3 条**。

---

## 0. 一句话

`(y + tick) & 1` 这个行扫描定向式子对**运动中**的粒子自我抵消失效，导致粉末堆积存在 −6.3% 的系统性右偏（32/32 种子同向）。改为「每 tick 掷一次全局奇偶相位」后，该偏置降到 +0.04%（95% CI 跨 0，9/16 分布 = 纯噪声）。

---

## 1. 发现经过

用户在目检 Layer G Task 1 的 `out/mixed_disp5.gif` 时发现画面左右不对称，提出质疑。排查后确认**与 Task 1（液体色散）无关**，是既有缺陷：

- `powder_step`（`crates/sand-core/src/rules.rs:98`）从不调用 `side()`，色散对粉末无作用路径；
- 实测印证：`mixed_disp1.gif` 与 `mixed_disp5.gif` 的沙分布**逐列完全相同**（0 列有差异）。

GIF 里另一处"水位左右不平"经查是**正确行为**：沙堆在 x=159..164 堆到 y=154，高过右池水面，把盆地切成两个不连通的池子，水位本就可以不同。

## 2. 根因

### 2.1 每行内部的偏置（不打算动）

单缓冲原地更新的固有产物：同一行中先被扫到的粒子斜向移动后，会占掉后来者的反向目标格。仪器实测（对称挡板场景）：

| 行扫描方向 | 斜左 | 斜右 | 偏差 |
|---|---|---|---|
| LTR（左→右扫） | 10639 | 28184 | **+45.19%** |
| RTL（右→左扫） | 20515 | 8466 | **−41.58%** |

两类几乎等量反向 —— **`(y+tick)` 交替的设计意图是正确的**，问题不在这一层。根治需要改成"延迟提交"（一遍收集意图、二遍确定性裁决冲突），代价是推翻 Noita 式单缓冲地基、破坏 tick 内链式移动语义（那是液体摊平速度的来源）、重写 O1 活矩形的整个等价性论证。**不做，记入待决。**

### 2.2 交替为什么没抵消掉（真正的 bug）

两类行的**移动总量不等**：LTR 38823 vs RTL 28981（差 34%），正负加权不平，净 +8.11% 右偏。

原因：**下落粒子 `y+1`、`tick+1` 使 `(y+tick)` 奇偶恒定**，整个下落/塌落过程被锁死在同一扫描方向，交替机制只对静止粒子生效。

更一般的表述（由对照实验倒逼得出，见 §3）：**任何周期为 2 的定向方案都会与周期为 2 的动力学共振**。`(y+tick)&1` 锁死的是自由下落者；`tick&1` 锁死的是"动一拍、停一拍"的振荡者，实测反而更差。

### 2.3 第二个独立偏置源（本提案不修）

镜像轴落在 **chunk 边界**上时，缝两侧的 chunk 属于不同相位（四相棋盘 `(cx&1, cy&1)`），单 tick 内处理次序天然不镜像。§3 的几何对照实验把它与 §2.2 完全分离开了。量级约 −0.8%，属四相调度的固有性质。**单独记入 §7 待决**，并给出一条可立即采用的规避措施（竞技地图的镜像轴不要压在 chunk 边界上）。

## 3. 实验与数据

全部用 `sand-harness render` + 逐列像素统计，判据 = 沙量左右差占总量的百分比。

### 3.1 逐步隔离

| 场景 | 偏差 | 说明 |
|---|---|---|
| 完全对称、纯沙、无挡板 | −1.4% | 基础量级 |
| 完全对称 + 挡板 | −6.6% | 挡板边缘溢出放大了偏置 |
| `mixed` 去掉水 | −18.8% | 与带水时**逐列完全相同** ⇒ 水无关 |
| `mixed` 原样 | −18.8% | |

`diag_side` 掷骰本身是公平的：378 万样本，先试右 50.010%。**排除 RNG 偏斜。**

### 3.2 定向方案对照（对称挡板场景，32 种子，1500 tick）

| 方案 | 均值 | 95% CI | 同向 |
|---|---|---|---|
| `(y + tick) & 1`（原） | **−6.266%** | [−6.46, −6.07] | 32/32 |
| B：逐行哈希 `hash(tick, y)` | −1.169% | [−1.27, −1.07] | 32/32 |
| **B′：每 tick 全局相位 `(y ^ flip)`** | **−0.769%** | [−0.84, −0.70] | 32/32 |

三者都仍不跨 0 —— 说明还有第二个偏置源没被消除。（单种子曾测得 `y&1` 给出 +0.07%，**那是运气，不是无偏**；32 种子下站不住。这条教训值得记：单点数据不能证明"偏置消失"。）

### 3.3 分离第二个源：镜像轴 vs chunk 边界（16 种子，512×192）

| 镜像轴 | 原方案 | B′ |
|---|---|---|
| x=256（**chunk 边界**） | −6.383%，16/16 同向 | −0.795%，16/16 同向 |
| x=224（**chunk 正中**） | +1.705%，15/16 同向 | **+0.042%，95% CI [−0.044, +0.127] 跨 0，9/16** |

**结论**：B′ 在相位对称的几何下把扫描方向偏置**彻底消除**（9/16 的分布与 CI 跨 0 是教科书级的噪声特征）。chunk 边界那一栏残留的 −0.795% 完全来自 §2.3 的第二个源，与行扫描定向无关。

注意原方案在两种几何下**符号相反**（+1.705% vs −6.383%），说明两个偏置源会相互干涉 —— 这也是为什么必须做几何对照才能把它们分开。

## 4. 方案：B′（每 tick 全局奇偶相位）

```rust
// crates/sand-core/src/rules.rs::update_chunk
let flip = scan_flip(fseed);            // 每 tick 掷一次
...
let ltr = (y as u64 ^ flip) & 1 == 0;   // 原为 (y + tick) & 1 == 0
```

```rust
// crates/sand-core/src/rng.rs
pub const STREAM_SCANDIR: u32 = 4;
pub fn scan_flip(fseed: u32) -> u64 {
    ((rng_u32(fseed, STREAM_SCANDIR, 0, 0, 0, 0) >> 16) & 1) as u64
}
```

### 为什么是 B′ 而不是 B 或 `y & 1`

| | 无周期（抗共振） | 相邻行必反向 | 每 tick 行方向对偶 | 实测（相位对称几何） |
|---|---|---|---|---|
| `y & 1` | ❌ | ✅ | ❌（永久固定） | 单种子 +0.07%（不可信） |
| B 逐行哈希 | ✅ | ❌ | ❌ | −1.169% |
| **B′** | ✅ | ✅ | ✅ | **+0.042%（跨 0）** |

- **`y & 1` 不可取**：方向对每行永久固定，任何被约束在少数行内的结构（一格宽沙柱、贴地薄层、平台边缘）会拿到永久且无抵消机制的方向偏好。它的低偏差是**空间平均**的结果，不是局部无偏。且 Layer G Task 2 让粒子每 tick 跨 n ∈ 1..4 行后，`y&1` 在 n 为偶数时重新锁死（原方案则在 n 为奇数时锁死，而 **n=1 正是今天这个 bug**）。
- **B 丢掉了对偶变量方差缩减**：逐行独立掷骰后，单 tick 内 LTR 行数有 O(√N) 涨落，会出现局部方向一致的"剪切带"；粉末无回复力，这类瞬时不对称会被结构记住。实测也确实劣于 B′。
- **B′ 对任意 n 都不锁死**：方向变化量 = `n + (flip_{t+1} XOR flip_t)`，含随机项。

### 三个关键设计选择

1. **key 只取 `tick`（经 `fseed`），不掺 `x`/`y`/chunk**。方向若随 chunk 变，物理行为就会依赖 chunk 划分，在竖缝上引入新的各向异性 —— 而竖缝本就是伪影高发区。同一行在所有 chunk 必须同向。
2. **取 bit16 而非 bit0**。`rng_u32` 的 `pos` 是线性折叠、不是单射，存在一条格子集合使 `rng_u32(DIAG, x, y)` 与 `rng_u32(SCANDIR, 0, 0)` 返回**完全相同的 u32**（`P_X` 为奇数可逆 ⇒ 解唯一）。当前该列远在任何世界宽度之外，但那是**凑巧安全而非构造安全**。与 `diag_side` 的 bit0 错开一位代价为零，并有执法测试 `rng::tests::scandir_bit_independent_of_diag_bit` 守住 squirrel5 比特间无相关这个承重前提。
3. **流编号 4 而非 3**。3 已由 Layer G Task 2 的 `STREAM_FALLSTEP` 预留、5 留给 Task 3 的 `STREAM_SPLASH`（velocity spec §4.2③/§6.1）。一次排好，避免撞号后被迫改常量、再作废一次 golden。

## 5. LiveRect 逐位等价性论证（承重复核）

O1 活矩形的等价性论证（`docs/superpowers/specs/2026-08-30-o1-live-rect-design.md` §1）把三种 ScanMode 的逐位等价建立在"全扫访问序 V"上，而 V 的定义**字面依赖** `(y+tick)` 奇偶定向。本提案改了定向，故必须重新论证。

**论证保持成立**，理由：V 的等价性只用到三个性质 ——（a）V 是全序且三模式下相同；（b）活矩形扫描访问 V 的子序列；（c）扩张规则把"在自己 V 时刻之前变得可动"的 cell 纳入本遍。代码侧真正承载它的是 `rules.rs` 里**「起点用快照、终点每步重读」的非对称结构**（`rules.rs:52` 的 `row` 快照 vs `:55`/`:61` 的动态终点），**这个结构对方向取哪个值不敏感** —— 方向只决定"未访问侧"是左还是右。

因此只需保证性质（a）：方向在三模式下取值一致。`flip` 来自 `fseed`（`scheduler.rs:47`，由 `(world.seed, tick)` 算出，三模式同值），`y` 是全局行号 —— 两者都与起始矩形、`dirty`/`next_dirty`、chunk 是否唤醒、线程调度无关。✅

**由此升格出一条新红线**（此前是隐含前提，改动后变成显式承重条件）：

> **行扫描方向必须是 `(tick, y)` 的纯函数。禁止让它读 `WriteWindow::live_rect`、扫描起始矩形、`own_ci`/chunk 坐标、`dirty`/`next_dirty` 或任何线程上下文。**

违反即三种 ScanMode 分叉。已写入 `rules.rs::update_chunk` 与 `rng::STREAM_SCANDIR` 的文档注释，执法靠 SyncTest 六配置。

**活矩形不会病态膨胀**：`live` 只经 `merge_point` 单向扩张且在 `window.rs` 被夹进本 chunk，单遍最坏 = 全扫（恰好退化为 ChunkSleep 成本），不存在超过全扫的可能；循环终止条件与活矩形无关；行内向前方写出的 cell 带 `stamp`，走到时被 `rules.rs:71` 跳过，不形成传送带。

## 7. 待决与后续

1. **chunk 相位分解的镜像不对称（§2.3）**，残留约 −0.8%。属四相棋盘固有性质，修它要动总纲 §4 的核心调度。**可立即采用的规避**：竞技地图的镜像轴不要压在 chunk 边界（64 的倍数）上 —— 放在 chunk 正中即可把它降到噪声级（§3.3 实测）。是否需要真修，建议留到 M4 有真实对战地图后按实际量级决定。
2. **单缓冲先手占位优势（§2.1）**，±45% 的行内偏置。延迟提交是唯一根治路线，代价极大，记入长期待决。本仓库已有先例可参考：fire spec 的延迟点燃队列正是为了"防帧内沿扫描方向的连锁偏置"。
3. **液体未受此问题困扰**（实测 ±0.4%），因为摊平有回复力会持续抹掉偏斜；粉末无回复力所以永久累积。M2 之后新增的粉末材质（灰烬、火药、雪）会共享本提案的修复。
