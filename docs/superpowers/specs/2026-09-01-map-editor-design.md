## 0. 验收标准

1. 浏览器里画一张油-木图 → "保存并渲染" → 页面内出 GIF；再"加载"回来，网格与所画逐格一致。
2. 老场景（纯 `Fill`/`Brush`）可加载进编辑器（走 `rasterize`），导出后语义不变。
3. 不写 `grid` 的既有场景 golden/SyncTest **逐位不变**（现有执法测试即证明）。
4. harness 单测：RLE 解析与全部加载期报错路径、`grid`→`setup` 铺设顺序、`rasterize` 往返恒等。

## 1. 四条用户裁决（2026-09-01）

1. **深度：B 改完即渲**——纯编辑器太"哑"；wasm 实时模拟留作后续升级路径。
2. **边界：C**——第一版只画初始网格，文件格式内嵌网格进场景文件，时间线（`script`）字段存在但先手写。
3. **存储格式：B `grid` 字段**——行级 RLE 文本 + 图例，按材质名而非 id。
4. **胶水：A Python 标准库**——工具层不受"游戏逻辑用 Rust"约束；数据契约仍由 harness（Rust）落实。

## 2. 架构与数据流

`tools/map-editor/` 是四环之外的开发工具。它只碰两种数据文件（读 `data/materials.ron`、写 `data/scenarios/*.ron`）和 `sand-harness` 二进制。内核与 harness 的确定性语义不动；唯一正式契约是场景文件新增的 `grid` 字段，由 harness 解析与校验。

```
浏览器画布 ──POST 场景文本──▶ serve.py ──写文件──▶ data/scenarios/<name>.ron
                                    └──子进程──▶ sand-harness render → out/<name>.gif ──▶ 页面显示
浏览器"加载" ◀──JSON 网格──── serve.py ◀──子进程── sand-harness rasterize <scenario>
浏览器调色板 ◀──JSON──────── serve.py ◀──子进程── sand-harness materials --json
```

回读走 harness 的**真实加载器**（`grid` + `setup` ops 一起铺好再读网格），页面自己不解析 RON；老的纯 `Fill` 场景因此也能载入。

## 3. `grid` 字段契约（harness 加载期，全部显式报错）

```ron
grid: (
    legend: { '.': "air", 'W': "wall", 'o': "oil", 'w': "wood", '~': "water" },
    rows: [
        "256.",
        "2W 60. 40o 154.",
        // … 共 height 行
    ],
),
```

- **图例**：单字符 → 材质名。字符重复、材质不存在 ⇒ 报错。`'.'` 不特殊，由图例说了算。
- **行**：`rows.len()` 必须 = 世界高度（`height_chunks × 64`）；每行 token 形如 `<count><char>`，count 省略即 1，token 间空白可选；展开后长度必须 = 宽度；未知字符 ⇒ 报错。
- **铺设顺序写死**：`grid` 先铺，`setup` ops 再叠。`grid` 缺省 = 不铺（老场景零变化）。
- **写入路径**：每个非 air 的 RLE 段编译成一条 `Op::Fill{x0..x1, y}`（见下"实现位置"），最终经 Brush/Fill 同一条 `set_cell_stamped` 路径落格（盖戳、脏矩形、液体/气体 dir 初始化、lifetime 装填）。air 段不生成 Fill——世界初始即 air，`set_cell_stamped(air)` 与初始态逐位相同，跳过不改变语义。
- **指纹**：场景字节哈希（行尾归一化后）已覆盖 `grid` 文本；解析结果是纯整数展开，无需像 `Op::Emit` 的 `Fx` 那样二次折叠。
- **实现位置**：`sand-harness/src/scenario.rs` 新增 `GridSpec` 反序列化 + `expand_grid() -> Vec<Op>`，把每个非 air 的 RLE 段转成一条 `Op::Fill{x0..x1, y}`，作为 **`Scenario::setup` 的前缀**（`load_scenario` 里拼接：grid 段在前、文件里的 setup ops 在后）。`Scenario` 结构不加新字段、`runner::build_sim` 不改、`Sim::apply_setup` 照旧——**core 零改动**，铺设语义与手写 Fill 完全等价。

> 上一条是本 spec 的关键取巧：`grid` 在 harness 内部**编译成 Fill 前缀**，core 与 `Sim` 接口一字不动，所有既有写入纪律自动继承。

## 4. 两个只读子命令（`sand-harness/src/main.rs`）

- `sand-harness materials --json [--materials PATH]`：输出 `[{id, name, color:[r,g,b], category}]`。
- `sand-harness rasterize <scenario.ron> [--materials PATH]`：建 Sim、`apply_setup`（含 grid 前缀）、不 step，读整幅网格输出 `{width, height, legend:{char:name}, rows:[…]}`——legend 由材质表生成（air 固定 `'.'`，其余优先材质名首字母大写/小写，冲突再按 id 序从固定字符池补——`scenario::default_legend`），rows 用与 §3 相同的 RLE 编码，可被编辑器原样再导出。

两者都不产生副作用，不进 golden。

## 5. 页面（`tools/map-editor/index.html`）

单文件、无框架、无构建。

- 画布 = 世界尺寸整数倍放大；新建时选 `(宽 chunk, 高 chunk)`；显示坐标与 **chunk 缝线**（64 倍数处，对齐时避开镜像轴压缝的已知偏置）。
- 工具：笔刷（1/2/4/8 方块）、矩形填充、油漆桶（4 连通）、橡皮（= 画 air）、吸管；调色板来自 `/materials`，颜色与 GIF 一致；撤销/重做（按笔画）。
- 侧栏：场景名、seed、ticks、渲染参数（`every / scale / from`）、`script` 原样透传文本框。
- 按钮：保存并渲染、加载（下拉 = `/scenarios`）、仅导出下载。
- 页面负责 RLE 编码/解码；导出文件头一行注释 `// generated by tools/map-editor`。
- 内存模型：`Uint8Array(w*h)` 存材质 id——这就是将来 wasm 实时预览的输入，格式已留门。

## 6. 服务（`tools/map-editor/serve.py`，Python 标准库）

- `GET /` 页面；`GET /materials`、`GET /scenarios`、`GET /load?name=`（分别是子命令 JSON 透传、目录列表、`rasterize` 透传）；`GET /out/<name>.gif`。
- `POST /save`：`{name, ron, render:{ticks, every, scale, from}}` → 名字白名单 `^[a-z0-9_]{1,40}$`（防路径穿越）→ 写 `data/scenarios/<name>.ron` → 同步跑 `target/release/sand-harness render`（超时 300s；失败把 stderr 原文回给页面）→ 返回 `{gif: "/out/<name>.gif", log}`。
- 只绑 `127.0.0.1:8765`；启动时找不到 release 二进制即提示 `cargo build --release -p sand-harness`。
- 访问：`ssh -L 8765:localhost:8765 sunyunbo@zhustation` → `http://localhost:8765/`。
- `tools/map-editor/out/` 入 `.gitignore`。

## 7. 测试

- **harness 单测**（`scenario.rs`）：RLE 省略 count / 空白 / 行数不符 / 宽度不符 / 未知字符 / 图例重复 / 图例未知材质；`grid` 编译为 Fill 前缀的顺序（grid 段在 setup ops 之前）；`rasterize` 编码器 ↔ `grid` 解析器往返恒等（随机网格 → rows → 解析 → 相同 id 数组）。
- **回归**：既有 golden/SyncTest 不变（老场景无 `grid`）。
- **端到端（用户手动）**：验收第 1、2 项。
