# 地图编辑器支线实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> 文档路径：`docs/superpowers/plans/2026-09-01-map-editor-plan.md`
> 最近更新：2026-09-01 (UTC+8)
> **Status**: Proposed

**Goal:** 浏览器里手绘场景网格，保存即渲染出 GIF；场景以 `grid` 字段（行级 RLE + 材质名图例）内嵌进现有 RON。

**Architecture:** harness 侧新增 `grid` 解析（编译为 `Fill` 前缀 ops，core/Sim 零改动）+ 两个只读子命令；`tools/map-editor/` 放单文件 HTML + Python 标准库服务，四环之外。

**Tech Stack:** Rust（sand-harness，serde/ron 已有）、Python 3 标准库、原生 HTML/JS Canvas。

**Spec:** `docs/superpowers/specs/2026-09-01-map-editor-design.md`

## Global Constraints

- core（`sand-core`）与 `Sim` 接口一字不动；`grid` 在 `load_scenario` 里编译成 `Op::Fill` 前缀（spec §3）。
- 加载期全部显式报错（图例重复/未知材质/行数/宽度/未知字符），与 M2 契约同纪律。
- 不写 `grid` 的既有场景 golden/SyncTest 逐位不变（现有测试即执法）。
- 新子命令只读、无副作用、不进 golden。
- serve.py 只绑 `127.0.0.1`，场景名白名单 `^[a-z0-9_]{1,40}$`；`tools/map-editor/out/` 入 `.gitignore`。
- 每 Task 收尾：`cargo test -p sand-harness` + `cargo clippy --workspace --all-targets` 绿、spec 进度表打勾、CHANGELOG 落账、单独 commit 推送。

### Task 1: harness 契约——`grid` 解析 + `materials --json` + `rasterize`

**Files:**
- Modify: `crates/sand-harness/src/scenario.rs`（`ScenarioFile` 加 `grid: Option<GridSpec>`；`expand_grid`；RLE 编解码器）
- Modify: `crates/sand-harness/src/main.rs`（两个子命令）
- Test: `scenario.rs` 内嵌单测

**Interfaces（Task 2 依赖）:**
- RON：`grid: (legend: {'.': "air", 'W': "wall"}, rows: ["256.", "2W 60. 40o 154."])`——`legend` 是 `BTreeMap<char, String>`（RON 的 char 字面量 `'W'`），`rows: Vec<String>`。
- `pub fn rle_decode_row(row: &str, width: usize, legend: &BTreeMap<char, u8>) -> Result<Vec<u8>, String>`：token `<count><char>`，count 省略即 1，空白可选；长度 ≠ width ⇒ Err。
- `pub fn rle_encode_row(ids: &[u8], symbols: &[char]) -> String`：`symbols[id]` 为该材质的图例字符；连续段输出 `"<count><char>"`，count=1 时省略，token 间单空格。
- `pub fn default_legend(table: &MaterialTable) -> Vec<char>`：air 固定 `'.'`，其余按 id 依次从 `"WsoOw~fSabcdeghijklmnpqrtuvxyz"` 这类可打印字符池分配（实现里用一个固定字符串，跳过 `.`；材质数超过池长 ⇒ Err）。`rasterize` 输出的 legend 由它生成。
- `expand_grid(spec, table, world) -> Result<Vec<Op>, String>`：非 air 段 → `Op::Fill{material, x0, y0: y, x1, y1: y}`；`load_scenario` 把结果放在 `setup` 前面。
- `sand-harness materials --json [--materials PATH]` → stdout JSON 数组 `[{"id":0,"name":"air","color":[16,16,24],"category":"Static"}, …]`（手写 JSON 拼接即可，避免加 serde_json 依赖；转义材质名里的引号）。
- `sand-harness rasterize <scenario.ron> [--materials PATH]` → stdout JSON `{"width":W,"height":H,"legend":{".":"air",…},"rows":[…]}`（`build_sim` + `apply_setup`，不 step，逐行读 `world().cell()` 编码）。

**要点：**
- [ ] TDD 单测先行：`rle_decode_row` 七条报错/正常路径（省略 count、空白、宽度不符、未知字符）；`legend` 重复字符与未知材质在 `expand_grid` 报错；行数不符报错；`expand_grid` 产出的 Fill 段坐标与顺序（行主序、grid 段在 setup 前）；`rle_encode_row ↔ rle_decode_row` 往返恒等（用 `rng::squirrel5` 生成伪随机行）。
- [ ] 实现 + `load_scenario` 拼接前缀；`Scenario` 结构不变。
- [ ] main.rs 两个子命令（`parse_args` 的 `scenario` 位置参数对 `materials` 子命令允许缺省——用 `"-"` 占位或把 `materials` 提到位置参数判断之前）。
- [ ] 用一个临时 `grid` 场景手工跑 `rasterize` 看输出格式；跑 `cargo test -p sand-harness`（golden 五个必须原样绿）+ clippy。
- [ ] 收尾：spec 进度 Task 1 ✅、CHANGELOG、commit `feat(harness): 场景 grid 字段（RLE+图例）+ materials/rasterize 子命令`。

### Task 2: `tools/map-editor/`——页面 + 服务

**Files:**
- Create: `tools/map-editor/index.html`、`tools/map-editor/serve.py`、`tools/map-editor/README.md`
- Modify: `.gitignore`（`tools/map-editor/out/`）

**Interfaces:**
- serve.py 端点：`GET /`、`GET /materials`（透传 `materials --json`）、`GET /scenarios`（`data/scenarios/*.ron` 名字数组）、`GET /load?name=`（透传 `rasterize`）、`GET /out/<name>.gif`、`POST /save`（body `{name, ron, render:{ticks,every,scale,from}}` → `{gif, log}` 或 `{error, log}`）。
- 页面状态：`grid: Uint8Array(w*h)`、`legend` 由材质表生成（与 harness `default_legend` 同一字符池，写死同一字符串）、撤销栈 = 笔画前的 grid 快照（`Uint8Array` 拷贝，上限 50）。
- 导出 RON 模板：
  ```ron
  // generated by tools/map-editor
  Scenario(
      name: "<name>", world: (<wc>, <hc>), seed: <seed>, ticks: <ticks>,
      grid: (legend: {'.': "air", …}, rows: [ "…", … ]),
      setup: [],
      script: [ <script 文本框原样> ],
  )
  ```

**要点：**
- [ ] serve.py：`http.server.ThreadingHTTPServer`，仓库根由脚本位置推出（`Path(__file__).resolve().parents[2]`）；启动检查 `target/release/sand-harness` 存在；`POST /save` 名字白名单 + 写文件 + `subprocess.run([...render...], timeout=300, capture_output=True)`；错误统一 JSON。
- [ ] index.html：Canvas 绘制（`ImageData` 一次性刷新）、工具条（笔刷 1/2/4/8、矩形、油漆桶 4 连通 BFS、橡皮、吸管）、chunk 缝线叠加层、侧栏参数、加载/保存并渲染/导出下载、GIF `<img>` 显示（加时间戳 query 防缓存）。RLE 编解码 JS 版与 harness 同规则。
- [ ] README：启动 `python3 tools/map-editor/serve.py`、隧道命令、格式速览、已知限制（第一版不编辑时间线）。
- [ ] 本地验证：启动服务 → `curl /materials`、`/scenarios`、`/load?name=fire_oil_chain` → 用 curl POST 一个最小场景走 `/save` 出 GIF。
- [ ] 收尾：spec 进度 Task 2 ✅、CHANGELOG、commit `feat(tools): map-editor——单文件画布 + Python 改完即渲服务`。
