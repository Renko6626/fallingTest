# 会话：水里的刚体越转越快（M3 浮力修订）

## 现象

用户目检：刚体在水里不稳，"旋转—加速—再旋转，直到旋转超级快"。

## 复现与取证（systematic-debugging）

- 探针：`Sim::body_state` 诊断视图（新增、保留）+ 临时逐 tick 打印（已删）。crate_yard 水塘里
  单放 32×6 木条 35° 入水：|ω| 从 1 单调爬到 22 rad/s，角度整圈环绕；20×14 木箱单放 |ω| = 0。
- 逐 tick 浮力探针：采样水面 `h` 在 102↔121 间乱跳（真水面 120），木条竖起时 `h` 贴着木条顶端，
  判 192/192 全淹没，v = −18 格/s（阻力限速）出水；横拍回水面时 arm = −9.1、ω = +9.8——力矩与 ω
  同号做正功。
- ASCII 地图（`crates/sand-core/src/body.rs` 的 `stamp_body` 排开路径）：木条周围是一座 15+ 格高的
  水丘贴着迎水面，尾流是空腔。排开的水以刚体**线速度**弹出，粒子落回迎水面随刚体走。

## 根因

1. `surface_line` 采紧邻 4 列、取中位数——正好被自溅水丘俘获，读数只会偏高，偏高是正反馈。
2. 阻力只阻线速度（`apply_drag`），角速度零耗散（Rapier 缺省 angular damping = 0），能量只能
   留在旋转里。
3. 淹没量整行计数：`a04ebd0` 说明里的"像素分数"并未落地。32 宽木条一行 = 200 格/s² 的力阶，
   平衡点在台阶立面上，浮体每 tick 在 ±1.7 格/s 间抖，永远过不了 1 格/s 睡眠阈值。

## 修

`crates/sand-core/src/body.rs`：`surface_line` 取最低者 + 每侧再加隔 3 格的远 2 列 + 先碰邻体的列
作废；`apply_buoyancy` 按像素连续世界中心与 `y ≥ h` 的竖向重叠分数计权，同一 `K_DRAG` 补角阻力
`−K·Σw|r|²·ω`（`physics.rs` 的 `apply_angular_drag`）。

## 验证

- 单测 16 绿（`surface_line_and_submerged_count` 改为"取最低者"，新增邻体挡列用例）。
- 行为测试 17 绿，新增 `plank_in_deep_pool_does_not_spin_up`（|ω| < 6、1500 tick 后 < 0.5、入睡）。
  实测木条 |ω| 峰 1.6、tick 500 入睡；三体同池 tick 2000 前全部入睡。
- `cargo test --workspace` 全绿（crate_yard golden 重录；六配置 2 万 tick SyncTest 325 s 零分叉）。
- bench `crate_yard` 5000 tick：1T 1.066 → 0.720 ms，8T 1.050 → 0.768 ms（浮体能睡了）。

## 教训

- "施力不唤醒 + 收阈值"只是让浮体**有资格**睡；力是位姿的阶梯函数时它永远到不了阈值。
- 任何由环境采样决定大小的力，先问：刚体自己会不会改这个采样？会的话，取对自扰动**单调不利**
  的那一侧（这里是最低水面）。
- commit 说明里写了没落地的东西（"像素分数"），下一次目检就被当成已知事实绕过去了。

# 下午：方案 1 接触门控水面线

## 起因

用户追问："我在一个水槽正下方会不会莫名获得浮力？"四个布置实测：(A) 地上箱子隔 2 格空气挨着
玻璃水槽 ⇒ 升 35 格悬停在水槽水面高度入睡；(B) 架高水槽底板与箱子等高 ⇒ 升到 y=103 入睡；
(C) 水槽正上方、底板高于箱顶 ⇒ 无影响；(D) 一股水从旁边落下 ⇒ 抬 0.6 格。根因：`surface_line`
的采样列与刚体之间没有"接触"约束（穿墙采），上午加的远列把触达从 2 格扩到 5 格。

## 候选方案对照（详见 spec 决策记录第 14 条）

0 远场采样 / 1 接触门控 / 2 Noita 逐像素反作用 / 3 FSS v2 不盖章回调 / 4 wet 位记忆 /
5 湿面静水压。用户裁决先做 1；5 经检查有底面盲区（升力仍要借接触线）与"列高 ≠ 压强"
（水帘侧推 ≈ 2 倍自重）两条硬伤，2 免疫流水但没有静态浮力。

## 实施（三次迭代，每次都靠 crate_yard 盖章计数定位）

1. 接触选列 + 从接触向上扫连续液体：A/B 通过，但 35° 木条落水不减速砸到池底——下斜面邻格
   在本体正下方，向上一格即被挡，读数 = 底边 ⇒ 升力零。加"被刚体挡住的列作废"。
2. 通过后木条永久浮沉；加向外远列后仍每 tick 重盖章（1500/1500，弹水 5000 粒）；去掉紧邻列
   仍 1500/1500。不是距离问题：向上扫连续液体会塌到瞬时气泡处，"取最低"恰好选中它。
3. 读数改回自上而下（AABB 行带内首个液体），列仍由接触门控：盖章 476/1500（HEAD 536），
   bench 0.72 → 0.64 ms/tick，全部测试绿。

## 验证

单测 18（接触 / 挡列 / 气泡三条新增）、行为测试 19（A、B 两条新增）、workspace 全绿
（golden 重录、六配置 SyncTest 318 s 零分叉）、clippy 零警告。

## 教训

- 判读浮体方案好坏，看**清醒刚体每 tick 是否重盖章**（`stamp_all` 计数），比 avg 更早暴露。
- "取最低者"与"向上扫连续液体"不能同时用：前者放大任何偏低读数，后者制造偏低读数。
- 在 `git stash` 前后别对同一文件再 `git checkout`——工作树实现被回滚过一次，靠 scratchpad
  里的改动脚本重放救回。

# 傍晚：漏水段 + 睡眠浮体唤醒 + Noita 路线备忘

- `crate_yard` 加 tick 1200 炸穿左池壁（wall durability 15 > 缺省门槛 10，须显式给
  `max_durability: 15`；壁厚 4 格 × hp 100，power 1200）。渲染后用户指出木箱/木条挂在半空——
  探针证实两者从 1150 到 2950 一直 Z，y 不动，水面从 120 退到 150。
- 根因：昨天"施力不唤醒"让浮体能睡，水不是碰撞体、退掉不唤醒，浮力只算清醒刚体。
- 修：睡眠刚体周围 chunk 脏才重采 `h`，与 `last_h` 相差 ≥ 2 行即唤醒。第一版按淹没量 5% 设门槛，
  木条睡了又醒 11 次（一行 = 17%，池面常年 ±1 行抖）；改 `h` 滞回后木条 tick ~475 入睡不再醒。
- 用户三问 Noita：① Noita 有没有睡眠——Box2D 有，但液体里的刚体因 `ApplyForce` 唤醒而永远醒着，
  水退跟落免费；② 远处不模拟——是，他们分母小，我们 lockstep 全场模拟没有；③ 性能——公式层面
  两者都可忽略，差在静止时 Noita 式每浮体 ≈ 0.1 ms/tick 的 CA 钱。裁决：先保留睡眠 + 唤醒，
  Noita 式记为提案 `docs/proposals/2026-09-03-noita-style-buoyancy.md`。
- 验证：单测 153、行为测试 20（新增 `sleeping_floater_wakes_when_water_drains`）、harness 全绿
  （golden 重录、SyncTest 371 s）、clippy 零警告；旧场景 bench 0.62 持平，新场景 0.94。
- 教训：唤醒门槛要对刚体尺寸无关（用行数不用比例）；给场景加段落后**必须**重看目检，
  "看起来随水位下降"是我先看错了一次。

# 夜：浮力尾巴收口

- 四项一起做，木条回归立刻炸：入水不减速砸池底 + 冲出水面到 y=59 + 睡不着。四项加环境变量开关
  二分：沉降闸门取 0 滤掉了入水扰动的接触（改 2 格/tick）；顶面载荷把全淹没箱子上方整根池水柱当
  水丘（判据改"高于周围自由面"）；ω×r 出射维持横摇（撤回）；密封支撑只加阻力挡不住 268 格/s
  （加向下速度截断）。
- 结果：单测 156、行为测试 24（新增 4）、harness 全绿（SyncTest 423 s）、clippy 零警告；
  bench ≈ +7%；`wake_up=true` 实测 +0.9 ms 入提案。crate_yard 木条改 tick 700 池右半生成，
  目检：扶正、漂浮、随漏水下降（下降有 ≥2 行滞后的阶梯感，t=1400 一帧能看出悬空）。
- 教训：一次落四项等于放弃了定位能力，靠开关二分才救回来——下次这种"尾巴清单"逐项落、逐项跑
  木条回归。
